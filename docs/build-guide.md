# 工训赛智能垃圾分类装置：从结构制作到省赛程序部署

本项目使用 **树莓派 5 + YOLOv8** 识别垃圾，通过 **STM32F103RCT6、CoreXY 平台、四舵机机械爪和二维云台** 完成分拣，并使用红外光幕、超声波传感器和 Qt 界面实现投料检测、满载提示及操作交互。

项目在我大三期间完成，制作时间为 **2025 年 12 月至 2026 年 3 月**。我负责机械结构设计、STM32 程序以及 YOLOv8 模型训练与部署；队友 **ccy** 负责树莓派端代码，并基于 **zsq** 学长的 Qt 界面完成适配。

本文按实际制作顺序介绍零件、装配、接线、标定和软件流程。软件说明以 `firmware/stm32/` 与 `software/raspberry-pi/` 中展开的 **省赛 3.19 版本**为依据。部分照片属于制作过程中的不同阶段，安装前应核对模型孔位、尺寸和自己的实物。尚未确认的采购规格不作为固定型号推荐。

## 系统如何完成一次分拣

投入口红外光幕检测到垃圾后，STM32 等待物体稳定，再请求树莓派拍照。树莓派识别物体类别和图像坐标：单个目标或全部同类时，控制托盘整体倾倒；存在不同类别时，先抓取一个目标，再重新识别剩余垃圾。倾倒后还会检查残留，最后进行满载检测并回到待机。

```mermaid
flowchart TD
    A[上电初始化与机械回零] --> B[串口解锁且等待约15秒]
    B --> C[等待红外投料触发]
    C --> D[等待2秒并发送 Start]
    D --> E[树莓派拍照识别]
    E -->|单个或全部同类| F[按类别倾倒]
    E -->|不同类别混合| G[按坐标抓取一个]
    G --> D2[再次发送 Start]
    D2 --> E
    F --> H[发送 Check 复检]
    H -->|还有目标| I[按坐标抓取残留]
    I --> H
    H -->|无目标返回9| J[满载检测与复位]
    J --> C
```

这张图描述正常识别路径。首次识别没有目标时的程序行为及其处理办法，见树莓派程序章节。

| 模块 | 制作内容 |
| --- | --- |
| 框架 | 2020 欧标铝型材、打印连接件和外壳 |
| 视觉 | 摄像头、树莓派 5、YOLOv8 模型、固定补光 |
| 水平移动 | CoreXY、两套步进电机及驱动器、回零限位 |
| 机械爪 | 旋转、双舵机伸缩、夹爪开合，共 4 个舵机 |
| 托盘 | 水平旋转与俯仰，共 2 个舵机 |
| 挡板 | 4 个舵机同步开合 |
| 检测 | 红外光幕、4 路独立触发超声波 |
| 交互 | 触摸屏、Qt/QML、工作灯及调试 OLED |
| 供电 | 锂电池、电源转换与上下部分配电 |

开始制作前，先准备可以查看和编辑 SolidWorks 模型的环境，确认自己要打印的零件版本，再制作型材和物料清单。工具包括装配螺丝工具、测量工具、焊接工具、万用表、3D 打印设备或打印服务，以及用于下载固件的调试器。需要切割光杆时，还要准备对应的切割与去毛刺工具。

制作时遵循模块逐个完成的顺序：先机械试装，再电气单独测试，最后进行整机联调。相机坐标标定安排在摄像头、托盘和机械回零位置都稳定之后。

## 机械装配过程

整个装置采用从上到下的安装顺序。顶部空间留给摄像头、CoreXY 和机械爪，中部安装托盘与挡板，底部安装四个收集桶。先把框架和运动机构装顺，再固定电池、电源及外壳，避免装好外设后又要拆开返工。

### 1. 确定尺寸并搭建铝型材框架

#### 1.1 先区分整机外尺寸、框架尺寸和型材长度

本机的设计尺寸目标是宽 400 mm、深 400 mm、高 600 mm。绘图时要将外壳算在整机尺寸里：如果左右两侧各覆盖 3 mm 厚的板材，框架在这个方向的外尺寸就应控制在 `400 − 3 − 3 = 394 mm`。并非所有方向都减同样的数值，具体取决于顶板、底板和侧板覆盖在哪里。

2020 型材的截面宽度是 20 mm。假设某横梁夹在两根立柱之间，其切割长度还需要从框架外宽中减去两侧立柱所占尺寸；若采用另一种搭接方式，则需要重新计算。**下单给商家的应是每根型材的切割长度，而不是整机宽度。**

保持 400 × 400 × 600 mm 这一级别的布局，有利于沿用现有托盘和挡板结构。若明显改变宽深、高度或摄像头位置，应一起检查托盘尺寸、挡板连接臂、CoreXY 行程和镜头覆盖范围。

#### 1.2 整理型材及连接件

框架使用 2020 欧标铝型材，主要分为三组：

| 分组 | 数量 | 位置 |
| --- | --- | --- |
| A | 4 根 | 四根竖直立柱 |
| B | 14 根 | 上下边框共 8 根、顶部中间横梁 1 根、底部中梁 1 根、四个侧面各 1 根横梁 |
| C | 2 根 | 分别接在底部中梁两侧，组成四分区支撑 |

B 组表示相同用途的一组横梁，实际能否全部等长取决于连接方式。先完成装配尺寸图，再确认各组长度。底部十字结构用于支撑云台和划分四个桶位，不需要用型材把每个桶围成独立框架。

连接件包括 2020 型材角码、配套螺栓、槽用螺母，以及固定打印件的螺丝。需要从型材端部滑入的螺母，要在封闭框架前放进去；可以从槽口装入的型号，也要核对槽宽是否匹配。

#### 1.3 实际安装顺序

1. 在平面上拼好底部边框，螺栓先拧到能保持位置，不立即完全锁死。
2. 安装四根立柱，再连接顶部四根横梁，形成长方体。
3. 测量上下框的对角线，调整框架方正，确认放在台面上不会翘角。
4. 安装底部中梁和两根分隔梁，预留中心云台安装位置。
5. 放入各侧需要使用的槽用螺母，安装四个侧面横梁。
6. 顶部中梁及屏幕附近的横梁先保留可拆卸状态，后面还要装投入口、屏幕固定件和摄像头。
7. 主要组件试装后，再统一锁紧并复测尺寸。

图中的框架照片用于说明型材位置，不同颜色或早期支架不影响这一步的型材布局。完成后应能清楚看到顶部安装区、中部托盘区和底部四个收集区。

### 2. 安装投入口及红外光幕

#### 2.1 检查投入口模型

投入口模型为 `hardware/mechanical/投入口.SLDPRT`。这个模型在比赛实践环节中调整过，所以打印前应先检查当前尺寸，确认上下卡槽、开口及四角安装孔与自己的框架匹配。

正对投入口时，上端连接顶部中间横梁，下端连接正面的支撑位置。先量出两处型材之间的净距离，再检查打印件能否放入。左右宽度不仅要容纳垃圾，还要给红外光幕的发射端、接收端及固定螺丝留空间。

如果需要重建模型，可先画投入口外框和开口，再设置上下与型材连接的部分，最后按光幕实物孔距增加固定孔。不要先把打印件做满两根型材之间的理论尺寸，再依靠强行挤压安装。

#### 2.2 将光幕固定在开口下方

红外光幕位于投入口下方，发射端与接收端相对安装。物体穿过开口后遮挡光束，STM32 据此判断发生了投料。

先把光幕固定到打印件上，检查两端高度和朝向一致，再将整个投入口装入框架。这里采用上下卡入型材的结构，先装投入口、后固定横梁会更容易。四角螺丝锁紧时不要把支架拉歪，否则可能导致部分光束无法正常对准。

线束从固定侧引出，贴着框架走线。不要让线束穿过投入口，也不要把接头藏在以后必须大拆框架才能拔出的位置。

#### 2.3 对应的电气与软件行为

省赛程序从 **PB13** 读取光幕信号，配置为上拉输入，读取到低电平时触发。购买的光幕必须确认输出形式与该逻辑匹配；供电线、信号线不能只凭颜色辨认。若模块输出电平与控制板不兼容，需要匹配的接口电路。

调试时先不让机械结构动作，只观察 PB13 在无遮挡和遮挡时的状态。用不同大小物体从左、中、右位置通过，确认信号都能变化。光幕检测到“有物体经过”，并不等于知道物体个数，因此后续数量和类别由视觉程序判断。

### 3. 安装显示屏并划分前部设备区

#### 3.1 理清正面空间

装置正面的横梁将安装区分成上下两部分。上部用于屏幕、屏幕驱动板、STM32 和接线；下部中间为投入口，左侧安排树莓派，右侧安排电池及电源模块。

此时先装屏幕及固定支架，树莓派、电池和电源可等 CoreXY 装好后再固定。这样能保留操作空间，方便拧紧内部螺丝和调整皮带。

#### 3.2 屏幕固定件安装

`hardware/mechanical/显示屏固定.SLDPRT` 需要打印两件，拼接后固定屏幕。使用前测量屏幕外框厚度、显示区域、驱动板位置和线缆插头方向。实验室使用的屏幕没有完整型号记录，更换屏幕后通常需要调整固定件。

安装时先拆下顶部阻挡打印件滑入的一根横梁，将固定件及屏幕试放进去，确认没有压住显示区域和排线，再装回横梁。不要依赖屏幕玻璃承受框架夹紧力，支撑应落在合适的外框或固定位置。

驱动板放在屏幕后侧的预留区域，固定前加绝缘支撑，避免电路板背面焊点接触金属型材。HDMI、USB 和电源插头周围保留拔插空间。

#### 3.3 屏幕接口与界面尺寸

本机屏幕使用 HDMI 显示、USB 触控及 12 V 供电，可选带扬声器。树莓派和屏幕之间的显示线应按两端实际接口购买，触摸功能另接 USB 线，不能只插显示线就期待触控工作。

省赛 `qml/main.qml` 的界面按 **1280 × 800** 固定尺寸设计，并以全屏方式打开。换成其他分辨率的屏幕后，需要检查布局、按钮和字体是否完整显示。

先单独点亮屏幕、验证触控，再进入后续安装。屏幕和驱动板固定后，确认螺丝及线头不会伸入 CoreXY 运动区域。

### 4. 安装摄像头并确定托盘拍摄范围

#### 4.1 安装摄像头支架

摄像头使用 `hardware/mechanical/摄像头.SLDPRT` 和 `hardware/mechanical/摄像头盖.SLDPRT` 两个打印件固定。先将摄像头放入支架，确认镜头不被遮挡，连接线能够自然引出，再装盖板。

整套支架安装在顶部中间横梁下方，镜头朝下。尽量让摄像头位于托盘上方的中间位置，而不是在偏向一侧的位置斜着拍摄。先保留支架微调余量，等托盘高度确定后，再调整拍摄范围并锁紧。

#### 4.2 选择镜头和安装高度

这个项目早期使用过约 60° 的镜头，后续更换过，最终视场角暂未确认。复刻时不要把不确定的 85° 当作固定采购参数。

在框架内先用纸板模拟托盘的轮廓和高度，打开实时画面，检查四个角是否完整进入画面。如果拍不全，应调整安装高度或镜头；如果画面包含大量托盘之外的区域，目标在图像里会变小，可重新选择覆盖范围。

理想状态是整个托盘都在画面中，边缘保留少量余量，且目标放在四角时仍然清晰。购买镜头时要区分商家给出的水平、垂直或对角视场角，最终以实拍检查为准。

#### 4.3 与机械爪共同检查空间

摄像头占据横梁下方的一部分空间，CoreXY 中心滑台经过这里时不能碰到摄像头支架、镜头和线缆。因此，摄像头不是装好后就完全不用再管：安装平台时要再次检查它的下方净空。

固定线束后，手动让中心滑台走过完整工作区，尤其检查滑台带着旋转舵机和接线板后的最高点。通过检查后再给平台通电。

更换镜头、分辨率、图像方向、摄像头位置或托盘高度后，需要重新进行像素坐标到机械坐标的标定。不能只让新画面“看起来差不多”，就继续使用旧系数。

### 5. 装配 CoreXY 平台、同步带与回零机构

#### 5.1 准备模型和传动零件

平台零件主要位于 `hardware/mechanical/XY平台/`。`Woodcore XY-CORE by Rics_3D - 2555558` 是参考设计资料（完整参考包在本地归档，见 `references/README.md`），照片中的结构可用于理解传动布局；打印与装配时应以本项目使用的零件组合为准。

需要两套步进电机及驱动器、6 mm 光杆、匹配的直线轴承、两条同步带、带齿轮和无齿惰轮，以及滑轨支架、滑台和电机支架等打印件。直线轴承的最终型号需同时核对内径、外径和长度，不能只确认模型安装孔约为 12 mm 就下单。

带齿轮按两类分别准备：第一类使用 6 个，第二类使用 2 个；无齿惰轮使用 4 个。可适量准备备件，但先核对齿距、带宽、轴孔及轮的有效宽度。采购图中的数量不作为装配数量依据。

#### 5.2 安装光杆、支架和滑台

先按模型确定光杆的实际长度，再切割并处理两端毛刺。把轴承装入对应滑块后，先在单根光杆上试滑，确认没有明显卡点，再装入框架。

两侧导向安装时保持平行，不要一边把支架锁死，另一边再靠用力掰正。可以先略微松开固定螺丝，让滑块沿行程移动，再逐步锁紧。若某一段明显变紧，检查光杆平行度、打印孔位和支架受力，不能依靠加大电机力矩硬拖过去。

安装中心滑台后，检查它在各方向的移动空间。这里的中心滑台也承担旋转舵机、夹爪和移动接线板，装好夹爪后的重量和外形都会增加，所以要保留结构余量。

#### 5.3 穿入两条同步带

`XY平台/Riemenklammer.stl` 需要打印两个，用于夹紧同步带端部。先把两条皮带的一端固定到中心滑台，再分别按照各自路径穿过电机轮和转向轮，最后将另一端固定回滑台。

检查时分开追踪每一条皮带，不要把两条带当作一条绕。逐段确认：这段带属于哪一层、接触轮子的齿面还是背面、经过转向后是否与另一条带摩擦。夹紧端部时，应确认皮带不会从固定件中慢慢滑出。

穿带完成后逐步收紧两条皮带，使其有稳定张力，同时仍能平顺推动滑台。不要把皮带拉到支架明显变形；张力过大也可能让轴承受力偏斜。先手动跑完全程，确认皮带不爬边、不脱槽、不磨打印件，再安装电机控制线。

现有照片没有完整展示每一段带路。实际穿带应结合模型和参考结构逐段追踪，不凭一张局部照片推测被遮住的路径。

#### 5.4 调整整个平台的高度

电机支架不必紧贴顶框安装。平台需要向下留出距离，保证中心滑台、旋转舵机及接线板经过摄像头下方时不发生碰撞。

先完成摄像头位置和滑台试装，再上下调整平台支架。高度越低，托盘上方的抓取空间越小，因此要在“避开摄像头”和“给夹爪留下伸缩行程”之间协调，而不是直接照照片估算一个高度。

#### 5.5 安装两个限位开关

限位开关分别安装在固定支架和中心滑台附近，用于判断滑台是否到达回零角落。固定开关前，手动把滑台移到目标位置，确认触发的是开关拨杆而不是直接撞击开关本体；到位后应仍有少量机械余量。

回零由步进驱动器完成，省赛 STM32 程序没有为这两个开关定义独立输入引脚。开关应接到执行回零的驱动器限位接口，具体端子和有效电平要按所用驱动器版本确认。

若使用两个常开触点串联，只有两个触点同时闭合，通路才闭合；驱动器能否将此解释为到位，还取决于输入逻辑。不能把两个常闭触点串联后认为逻辑与前者相同。

#### 5.6 配置延时上电回零

本机采用一台电机先回零、另一台电机通过继电器延时供电的方式。先上电的驱动器开启“上电回零”，并设置匹配的方向、限位条件和速度；后上电的驱动器不执行自己的上电回零。

回零阶段，后上电电机不主动保持位置，转子可被皮带带动。先上电电机带动机构向初始角落运动，限位条件满足后停止。由于这种做法依赖具体传动和限位布置，首次调试必须降低速度并检查完整路径。

STM32 用 **PB6** 输出继电器控制信号：初始化为高电平，约 15 秒后变为低电平。只有当继电器接法与这个电平变化相匹配时，才能实现第二台电机的延时上电。先不接电机负载，验证继电器在上电和 15 秒后的状态，再连接驱动器电源。

这里没有从驱动器返回给 STM32 的“回零完成”反馈，程序只等待固定时间。因此机械回零必须在延时结束前完成；卡住或限位失效时，STM32 并不知道实际没有回到原点。

### 6. 组装四舵机机械爪并整理移动线束

#### 6.1 分清四个舵机

机械爪包含旋转舵机 1 个、伸缩舵机 2 个、开合舵机 1 个。旋转舵机直接安装在 CoreXY 中心滑台，下面连接伸缩支架，末端连接夹爪。支架与装配参考主要位于 `hardware/mechanical/垃圾桶/`，末端夹爪可使用配套购买的金属结构。

先把四个舵机贴上“旋转、夹爪、伸缩 A、伸缩 B”标签，避免接线和调试时认错。两个伸缩舵机需要机械配合，不能因为都有 PWM 信号就认为安装方向一定正确。

#### 6.2 舵盘安装前先设定角度

将舵机接入控制器，在不带负载时给出明确的参考角度，再装舵盘与连杆。90° 可用作初步装配参考，但完整程序的初始角度不是全部 90°：旋转为 85°、夹爪为 40°、伸缩为 70°。

推荐先用 90° 检查舵机能否稳定定位，再结合上述程序初始值确定舵盘安装方向。固定舵盘前确认连杆处于预期姿态，固定过程中不要手动拧动输出轴。若花键齿位无法正好对齐，微调程序角度，而不是强行扭住舵机安装。

机械爪运行时使用的下降、抓紧、抬升和张开角度，还要在实物上逐项校准。所谓“夹紧 105°”只是舵机的控制目标，不代表夹爪一定以某个固定力夹住所有物体。

#### 6.3 组装伸缩结构

先装旋转舵机和上部支架，再安装两个伸缩舵机及两侧连杆，最后连接下部夹爪。所有转动连接应检查能否自由活动，螺丝不能把连杆夹到转不动，也不能松到存在明显侧向晃动。

两个伸缩舵机由程序输出相同角度，分别使用 PB0、PB1。安装时需要让两侧结构在相同指令下共同向下或共同抬起。如果一侧下压、另一侧上提，先检查舵盘和连杆方向，不能长时间通电让两个舵机互相顶住。

先试一个很小的伸缩范围，确认动作协调，再逐步接近工作高度。夹爪下降到托盘附近时，需要保留不会撞击托盘的余量，并考虑目标自身高度。

#### 6.4 制作移动接线板

中心滑台上的接线板用于汇集四个舵机和限位开关线束，便于拆装。四个舵机各有电源、地和信号；在板上进行合适的电源分配后，对外可保留共享电源正负两根、四路信号以及限位触点两根线。

接线板采用 3 个 4 pin 可插拔接头时有 12 个针位，不代表必须使用全部针位。先画清针脚分配并贴标签，再焊接。是否共用一对供电针脚，需要按电流、线径和接头额定能力确定，不能只为了减少线数而把电流集中到过小的接点。

接线板装在中心滑台上，同步带紧固件位于相邻位置。应先确认皮带固定可靠、滑台运动顺畅，再安装接线板。板背焊点做绝缘处理后固定，线束出口做应力释放，避免移动过程中靠焊点承受拉力。

#### 6.5 为移动线束留出行程

先将滑台移动到离固定线束出口最远的位置，再确定线束长度；接着移到最近的位置，检查多余线束是否会掉入皮带和夹爪。最后依次检查四角和中间位置。

图中的理线打印件用于约束线束走向。它应引导线束弯曲，而不是把线束绷紧。所有动作检查完成后再扎紧，保留拆卸夹爪和接线板所需的插拔空间。

### 7. 制作带轴承支撑的二维云台

#### 7.1 为什么增加轴承

托盘既要承接从投入口落下的物体，又要旋转和倾倒。若整个托盘仅靠舵机输出轴和一个薄连接点支撑，落物冲击容易让机构晃动。这里给水平旋转部分增加独立轴承支撑，舵机负责驱动，支撑结构共同承担机械载荷。

所需主要打印件为 `底部舵机固定.SLDPRT`、`轴承舵机连接件.SLDPRT`、`轴承紧固.SLDPRT` 和 `旋转托盘.SLDPRT`，轴承型号为 6810ZZ。

#### 7.2 先安装底部水平舵机

将底部舵机放进 `底部舵机固定`，先检查固定耳、线束出口和螺丝空间。这个底座下方的圆弧用于避让压缩杆；不安装压缩杆时，可以修改该区域增加支撑面积，但不要封住舵机走线和固定孔。

舵机连接 PA0 对应的水平 PWM。设置到 90° 后，再固定舵盘；程序将这个位置作为托盘水平旋转的中间位置。舵盘使用舵机配套的小圆盘，安装时核对花键规格与固定螺丝。

#### 7.3 安装轴承和旋转连接件

先用舵盘连接 `轴承舵机连接件`，再将 6810ZZ 轴承放入设计槽位。核对哪一部分是固定支撑、哪一部分随托盘转动，避免用压盖同时锁住应转动的部分。

安装 `轴承紧固` 后，检查轴承是否被可靠限位，同时旋转部件仍可顺畅运动。若压盖拧紧后明显变涩，检查打印尺寸、轴承是否歪斜、螺丝是否让打印件变形。

最后安装 `旋转托盘`，将其与上部俯仰舵机和铝合金连接件组成完整云台。此时先不装大托盘，单独检查水平旋转和俯仰动作。

#### 7.4 安装俯仰机构并检查角度

俯仰舵机接 PA1。省赛程序的托盘复位角度为水平 90°、俯仰 94°，所以不能只根据机械上“看起来水平”就把程序的 94°改成 90°，应先校准舵盘安装关系。

完整倾倒动作会将水平转至 45°或 135°，俯仰转至 48°或 140°。先在没有垃圾的情况下逐渐测试这些位置，检查支架与框架是否干涉，再安装托盘并承载试验。

若改用现成的带支撑云台，可以省去部分打印装配，但需要重新检查高度、孔距、负载和活动范围，现有托盘接口及角度参数也可能要调整。

### 8. 安装托盘、四路超声波和黑色覆盖件

#### 8.1 处理托盘平整度

托盘打印完成后，先放到平面上检查四角是否翘起，中心连接区域是否平整。轻微翘曲可按材料特性处理；变形明显时应调整打印条件后重新打印。不要仅靠把四颗螺丝拧得很紧，把翘曲件硬拉到云台上，这会给连接处带来额外应力。

先用托盘主体与俯仰连接件试装，确认螺丝长度不会顶到舵机或活动件，再均匀锁紧。固定后托盘中心应与云台设计位置一致，避免偏心负载使倾倒晃动。

#### 8.2 在托盘四角安装超声波支架

超声波固定件的一面用于安装模块，背面与托盘角部贴合。先把模块放到平整的安装面，再将固定件背面粘接或按实际设计固定到托盘四角。

传感器要面向对应收集区域，不能朝向框架梁或挡板。托盘会旋转和俯仰，因此固定前先带着支架走一遍倾倒动作，检查探头、PCB 和接头是否碰撞下方桶壁。

线束沿托盘背面整理，再随云台留出弯曲余量。不能把传感器线拉得太紧，使托盘转动时直接拉扯模块针脚。

#### 8.3 按省赛工程接四路独立触发

四个 HC-SR04 分别使用独立的 Trig 和 Echo：

| 模块 | Trig | Echo |
| --- | --- | --- |
| 1 | PB14 | PC10 |
| 2 | PB12 | PC12 |
| 3 | PB5 | PC11 |
| 4 | PB7 | PB15 |

如果在合适的分配板上共用电源和地，对外仍需要 **2 根供电线 + 4 根 Trig + 4 根 Echo = 10 根线**。因此两个 4 pin 接口不足以承载这套独立布线。可重新选择接口数量，并标清各路编号。

程序依次测量四个模块，每路之间等待 100 ms，不是同时触发。第四路 Echo 的初始化有一处端口错误：头文件定义 PB15，但初始化函数把四路 Echo 都配置到 GPIOC。接好 PB15 后还需按软件章节中的说明修正初始化。

#### 8.4 安装黑色覆盖件

托盘固定完成后，覆盖黑色打印的 `托盘覆盖圆滑.SLDPRT`，遮住中间四颗螺丝。覆盖件边缘的圆滑过渡用于让垃圾倾倒时更容易滑落。

先检查覆盖件不会妨碍拆卸，不会在翻转时松脱，也不会把托盘边缘变成新的台阶。装好后把典型物体放到托盘不同位置，低速倾倒，观察是否在螺丝附近、边缘或覆盖件接缝处卡住。

最后开启补光检查画面。黑色背景和稳定照明是本项目的采集条件，更换颜色或表面材料后，需要重新验证识别和定位。

### 9. 安装四个收集桶、下部电源及走线管

#### 9.1 先检查收集桶的安装路径

底部十字型材把区域分成四格，中心安装云台，四个桶分别放入四格。桶体模型位于 `hardware/mechanical/` 中的对应文件，透明区域使用亚克力板配合制作。

不要只在 CAD 中确认“放进去以后不干涉”，还要确认桶体能从实际入口放进去。若云台、横梁或挡板装好后把桶的入口封住，应调整装配顺序，或把桶设计成可拆卸结构。

正式打印前，可以先打印局部角部或用板材模拟桶外形，确认尺寸及安装路径。桶体与框架之间留出装配间隙，不能依赖加热软化桶角后强行塞入。

#### 9.2 检查压缩机构相关结构

桶体和底部支撑曾为压缩推杆预留空间。基础版本不安装推杆时，可对避让区域作相应修改，保持桶体稳定支撑。取消某个部件后，要检查是否还有螺丝孔、开口或支架失去原来的用途。

四个桶装好后，逐一检查取出清理是否方便。不要把电源线永久压在桶底，也不要让满载垃圾取出时必须拔掉控制板上的细信号线。

#### 9.3 安装下部电源和方形走线管

下部 DC 模块为云台、挡板等负载分配电源。选择可以检查、调整和散热的位置固定，电路板与铝型材之间做绝缘处理，接线端子保留维护空间。

上下线路通过侧边黑色方管汇集。穿线前先按用途贴标签，确认线束长度能到达上部控制区。方管两端若有锐边，应处理后再穿线，避免反复移动或振动磨伤绝缘层。

云台和托盘属于活动部分，它们的线束应在进入固定方管前保留活动段；固定在桶壁上的线路则沿框架整理。把“固定线”和“随机构移动的线”分清，后面调挡板时会更容易发现干涉。

### 10. 安装挡板、补光与外壳

#### 10.1 一面挡板的装配关系

正对一面挡板，一端用 `侧面柱子固定.SLDPRT` 固定支撑光杆，另一端用 `侧面舵机固定.SLDPRT` 固定舵机。两端分别连接 `挡板固定.SLDPRT` 和 `挡板固定舵机.SLDPRT`，再将挡板本体连接在中间。

先把支撑端和舵机端装到两根立柱上，但不要立即锁死高度。让两端转轴在同一高度，再试放挡板。若两端高低不一致，挡板转动时会扭曲或卡住，不应靠舵机强行带动。

#### 10.2 校准关闭位置

四个挡板舵机共用 PA2 的 PWM 信号。程序将 52°作为关闭参考，将 80°作为打开参考。因此四个舵机的舵盘安装方向必须一致，机械连接还要保证同一信号能让四面共同打开。

可先在脱离挡板负载时设到同一装配角度，再固定舵盘；随后分别试到 52°和 80°，确认动作方向。不是把四个舵机都装成外观相同方向就一定能正确动作，还要看每面的连杆连接方式。

挡板装上后，上下移动两端支架，让关闭时的下边缘与托盘边缘贴合，相邻两块挡板的侧边也能靠近。不要把四边挤得没有间隙，否则打印尺寸误差可能导致其中一块先顶住，其他舵机仍在继续用力。

#### 10.3 为走线管安排缺口

带缺口的挡板安装在黑色走线方管所在一侧。先检查缺口是否真正避开管子，再检查打开时是否会夹住穿出的线束。挡板的适配关系同时涉及托盘、支架和框架，改变整机尺寸后应整体核对。

四个舵机由下部电源供电，信号线并接到 PA2，地线与 STM32 信号参考地连接。并联信号不等于可以由 PA2 给四个舵机供电。

#### 10.4 安装补光和外壳

三块 WS2812 灯板安装在三根立柱上，机械爪回零所靠近的角落不装灯板，避免挤占滑台和夹爪空间。可使用 `LED固定.SLDPRT` 对应支架，先确认灯板与实际打印件匹配。

灯板由 Arduino 控制，具体接线按所用板卡和灯板规格确认。先固定亮度与颜色，再采集训练图像；运行时保持相同照明条件。当前省赛 STM32 工程没有 WS2812 控制入口，不要将工作指示灯 PA12 当作补光数据口。

外壳安装前，先完成全部空载动作。确认摄像头线、灯板线和电源线都固定好后，再安装遮光板、亚克力装饰和侧边压条。至少保留便于断电、拔插和取桶的维护路径。

外壳装好后重新看一次摄像头画面，再做四方向倾倒和四角抓取测试。盖板可能改变内部光线，也可能压住原先没有干涉的线束。

## STM32F103RCT6 接线与供电

### 1. 控制板型号与端口名称

下文按 **STM32F103RCT6** 控制板说明接线，省赛 Keil 工程的器件项为 `STM32F103RC`。`PA0` 表示 GPIOA 的第 0 位，`PB10` 表示 GPIOB 的第 10 位；这些是芯片端口名称，不是开发板排针从左往右的序号。

接线时按控制板丝印找到对应端口。不同厂家的开发板，端口在排针上的排列、5 V 输入和 3.3 V 输出位置可能不同，不能照另一块板的排针顺序连接。芯片封装与电气参数参考 [ST 官方 STM32F103xC/D/E 数据手册](https://www.st.com/resource/en/datasheet/stm32f103rc.pdf)。

下面的功能分配来自省赛工程实际加入编译的源文件。未在控制板实物上核对的电源输入位置、继电器端子及驱动器接插件，不用猜测的针脚代替。

### 3. 十个舵机如何接到七路 PWM

十个舵机并不需要十个独立通道，分配如下：

```text
TIM2_CH1 / PA0 ── 云台水平舵机
TIM2_CH2 / PA1 ── 云台俯仰舵机
TIM2_CH3 / PA2 ─┬─ 挡板舵机 1
               ├─ 挡板舵机 2
               ├─ 挡板舵机 3
               └─ 挡板舵机 4

TIM3_CH1 / PA6 ── 机械爪旋转舵机
TIM3_CH2 / PA7 ── 夹爪开合舵机
TIM3_CH3 / PB0 ── 伸缩舵机 A
TIM3_CH4 / PB1 ── 伸缩舵机 B
```

每个舵机的电源正极接到符合舵机规格的电源输出，负极接对应电源地，信号线接表中 IO。控制板与舵机信号需要共同的地参考，舵机大电流回路应通过电源分配线路，不应穿过控制板细排针承担全部电流。

PA2 只分配 PWM 信号给四个挡板舵机。四个舵机能否同步到位取决于舵盘角度和机构安装；同一个信号不能补偿四个机构不同的机械偏差。

两个伸缩舵机分别用 PB0、PB1，但应用层同时给它们写入相同角度。布线保留两路，有利于之后分别微调。

### 4. 两台步进电机与继电器

#### 4.1 脉冲、方向和电机供电是三件事

| 电机 | 脉冲信号 | 方向信号 | 软件方向电平 |
| --- | --- | --- | --- |
| Left | PC0 | PC2 | `dir=0` 输出高，`dir=1` 输出低 |
| Right | PC1 | PC3 | `dir=0` 输出高，`dir=1` 输出低 |

PC0～PC3 接的是驱动器控制输入，不接步进电机线圈。电机线圈连接驱动器电机端，驱动器另接符合规格的电源。

驱动器的脉冲、方向接口可能使用单端信号或带正负端子的接口形式。应根据实际驱动器手册完成电平和公共端连接，不能仅凭 `PUL`、`DIR` 名称猜测要接到哪个正负端。

#### 4.2 继电器控制

PB6 连接适配 STM32 输出电平的继电器控制模块，不能直接驱动继电器线圈。继电器触点用于控制后上电那台驱动器的供电路径，触点容量应与负载匹配。

接负载前先检查以下状态：

| 时刻 | PB6 | 要实现的实际状态 |
| --- | --- | --- |
| 初始化后 | 高 | 后上电驱动器保持断电 |
| 约 15 秒后 | 低 | 后上电驱动器获得供电 |

这张表描述期望的接线结果。模块若是高电平触发，或用了不同的常开/常闭触点，实际状态可能相反，需要调整模块或接法。

限位开关连接到先回零的驱动器，本程序未接收它们的独立反馈。两台电机中哪台作为延时上电电机，需要按实物布置确认，不能仅凭软件名称 Left/Right 推定。

### 5. 四路超声波接线与初始化修正

四路 Trig 都在 GPIOB，但 Echo 分散在 GPIOB 和 GPIOC。`HC_SR04_Init()` 中将全部 Echo 位掩码合并后，只调用了 `GPIO_Init(HC_SR04_ECHO1_PORT, ...)`，而 `HC_SR04_ECHO1_PORT` 是 GPIOC，结果会配置 PC15，却没有按测距需要初始化 PB15。

接线按 IO 表不变，在 `HC_SR04_Init()` 中将“配置所有 Echo”的代码块替换为下面的分端口初始化：

```c
/* Echo1=PC10，Echo2=PC12，Echo3=PC11 */
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IN_FLOATING;
GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11 | GPIO_Pin_12;
GPIO_Init(GPIOC, &GPIO_InitStructure);

/* Echo4=PB15 */
GPIO_InitStructure.GPIO_Pin = GPIO_Pin_15;
GPIO_Init(GPIOB, &GPIO_InitStructure);
```

这是供复刻时采用的修正片段，省赛压缩包中的源码未被此文档自动修改。

模块 VCC 按模块规格供电，Echo 接入前确认输出电平与 MCU 引脚的兼容条件；需要电平转换时在接口处完成。信号线和电源线标明模块编号，特别注意模块 2 用 PC12、模块 3 用 PC11，不能按编号顺序想当然地接成 PC11、PC12。

### 6. 串口、OLED、红外与工作灯

树莓派通信只需发送、接收和信号地：

```text
STM32 PB10 / TX ───── 树莓派对应 UART 的 RX
STM32 PB11 / RX ───── 树莓派对应 UART 的 TX
STM32 GND      ───── 树莓派 GND
```

树莓派程序打开 `/dev/ttyAMA0`。这个设备名不等于已经确定了物理接线位置，尤其在树莓派 5 上，应先确认 UART 的启用方式和引出接口，再接对应 TX/RX。这里不把未经核对的 40 pin 排针编号写为固定连接方案。

调试 OLED 与主触摸屏是两个设备：OLED 接 PB8/PB9，用于显示四路平均距离；主屏通过 HDMI/USB 接树莓派。OLED 程序模拟 I²C，发送的写地址字节是 `0x78`，对应七位地址 `0x3C`，选模块时需匹配控制器与显示参数。

红外光幕输出接 PB13，程序以上拉输入读取低电平触发。工作灯控制在 PA12，待机时输出低、忙碌时输出高；实物灯的亮灭还取决于灯或驱动模块有效电平。不要仅凭函数名判断灯一定是高亮低灭。

### 7. 压缩接口与没有启用的模块

PA4、PA5 是压缩机构的两个控制输出，`Condense()` 依次输出：高/低保持 10 秒，低/高保持 10 秒，最后高/高。外部驱动器如何把这三个状态解释为伸出、缩回和停止，需要根据实际驱动电路确认。基础版本不连接推杆，也不操作界面压缩按钮。

工程目录中的 `TIM3_PWM.c`、`UART1_VOFA.c`、`LED.c`、`Key.c` 和 `TIM6_Timer.c` 没有加入当前省赛工程的编译列表。不能因为目录里存在某个文件，就把其中引脚当作当前接线依据。特别是 `TIM3_PWM.c` 和 `servo_drive.c` 存在同名函数，前者还是不同的 PWM 配置，不要同时添加到工程。

### 8. 分组供电与第一次通电

采用电池输入、多个电源分支的方式：树莓派用专用供电模块，上部机械爪和控制区、下部云台与挡板分别进行电源分配，显示器按其额定输入供电。步进驱动器、舵机、灯板和控制板不一定使用同一个工作电压。

第一次通电按以下顺序进行：

1. 断电检查各接插件电源正负，确认没有把供电与信号插反。
2. 暂时断开负载，测量各电源模块的输出，再连接对应设备。
3. 单独给控制板和屏幕、树莓派上电，先验证显示、通信与启动。
4. 舵机不带负载时逐个验证 PWM，再安装机械连接件。
5. 测试 PB6 及继电器的 15 秒状态变化，然后接入步进驱动器。
6. 低速验证回零与运动，最后才进入完整分拣。
7. 多舵机同时动作时观察是否掉电重启、画面中断或电源异常，确认后再装外壳。

## 省赛 STM32 程序详解

### 1. 打开正确的工程

打开 `firmware/stm32/Project.uvprojx`。本目录由省赛 `垃圾分类STM32_机械臂(3.19).rar` 展开，原压缩包位于本地 `.local-archive/original/代码/省赛代码/`。工程保存的编译器信息为 **ARMCC V5.06 update 5（build 528）**，目标器件为 `STM32F103RC`，启动文件为 `startup_stm32f10x_hd.s`。

`Hardware/` 放外设驱动与动作函数，`System/` 放延时和 TIM7 配置，`User/main.c` 是完整分拣入口。先保留工程原有文件列表，再进行参数修改，避免把目录里的测试文件全部加入编译。

`.local-archive/original/代码/垃圾分类STM32/` 是另一份工程，其中的 `main.c` 是单路超声波测试入口。它适合参考模块测试方法，但不用于替代本节的省赛主程序。

### 2. 时钟、定时器和 PWM 是怎样分工的

启动代码启用了 72 MHz 配置，非互联型分支使用 HSE × 9，头文件默认 HSE 为 8 MHz。Keil 工程元数据里还出现 12 MHz 的时钟字段，不能据此判断开发板实物晶振。烧录前应检查实际晶振、`HSE_VALUE` 和启动时钟配置相互匹配。

以下定时结果按程序预期的 72 MHz 定时器时钟计算：

| 资源 | 用途 | 配置与计算 |
| --- | --- | --- |
| TIM2 | 托盘水平、托盘俯仰、挡板 PWM | 分频 `72-1`，周期 `20000-1`，计数步长 1 μs、周期 20 ms |
| TIM3 | 机械爪四路 PWM | 同样为 20 ms 周期 |
| TIM4 | 步进脉冲的时间间隔参考 | 根据 `speed` 设置分频，轮询更新标志后翻转 PC0/PC1 |
| TIM6 | 超声波触发延时和 Echo 计时 | 分频 `72-1`，16 位计数 |
| TIM7 | 上电延时与红外检测重新使能 | 分频 `7200-1`，周期 `10000-1`，约每秒中断一次 |
| USART3 | 树莓派通信 | 115200，8 位数据，无校验，1 位停止位 |

舵机函数把目标角度转换为比较值：

```c
compare = degree / 180.0f * 2000 + 500;
```

在上述时钟下，0°、90°、180°分别对应约 500 μs、1500 μs、2500 μs 的高电平。这里说明的是程序输出关系，实际舵机能否覆盖这个范围，应按舵机规格和机械限位验证。函数没有自动限制输入角度，所以调用方不能随意传入越界值。

### 3. 从上电到等待投料

`main.c` 的初始化顺序为：

```c
workLED_Init();
OLED_Init();
UART3_OpenMV_Init(115200, 0, 1);
Catch_Init();
Low_Servo_Init();
IR_Init();
HC_SR04_Init();
Low_Servo_Reset();
```

逐项作用如下：

1. `workLED_Init()` 将 PA12 设置为输出并置高，设备先处于初始化状态。
2. `OLED_Init()` 初始化调试屏。
3. `UART3_OpenMV_Init()` 准备 PB10/PB11 通信和接收中断。
4. `Catch_Init()` 初始化步进控制 IO、机械爪 PWM，并启动 TIM7 的 1 秒节拍。
5. `Low_Servo_Init()` 初始化云台与挡板 PWM，并设置复位角度。
6. `IR_Init()` 设置光幕 PB13、继电器 PB6 和压缩控制 PA4/PA5。
7. `HC_SR04_Init()` 初始化四路测距 IO 及 TIM6。
8. 再次调用 `Low_Servo_Reset()`，确认托盘和挡板处于接收垃圾的姿态。

之后主程序先延时 1 秒，再等待串口接收标志。接收状态机刚启动时只接受字符 `'6'`，因此实际需要在树莓派界面进入识别页面，通过 `unlock()` 发送 `'6'`。

收到启动字符后，主程序还会等待 `Start_Flag`。TIM7 累计到约 15 秒时，将 PB6 拉低并把 `Start_Flag` 设为 1。也就是说，**界面已经打开，不代表设备立即可以投料；串口解锁和上电等待两个条件都要满足。** 这 15 秒从 TIM7 启动计时，不是从按下界面按钮开始。

### 4. 红外触发和三个流程标志

主循环使用以下标志区分是否要等一批新垃圾：

| 标志 | 作用 |
| --- | --- |
| `IR_Detected` | 本次读取光幕发现低电平遮挡 |
| `break_flag` | 混合垃圾抓走一个后，需要再次走 `Start` 识别流程 |
| `check_flag` | 已进行一次倾倒，随后进入 `Check` 清理复检流程 |

在普通待机状态，`break_flag`、`check_flag` 都为 0，主程序将 PA12 拉低，并持续调用 `IR_Detection_Process()`。

光幕触发后，函数将 `IR_Detected` 设为 1，暂时关闭重复检测，并等待 50 ms。TIM7 每秒清除 `IR_Detected`，对关闭检测的时间进行累计，经过三个计时节拍后重新允许检测。

这并不是一套“整轮分拣结束后才重新使能”的严格忙碌锁。是否等待新投料还由主循环及 `break_flag`、`check_flag` 决定。因此操作时应遵守工作指示状态，不在忙碌期间连续投料。

普通新投料触发后，STM32 等待 **2 秒**，让垃圾落到托盘并稳定，然后发送 `Start\n`。如果正在处理前一轮的后续动作，就跳过这段新投料等待。

### 5. 一次识别结果回来后，主程序做什么

发送 `Start\n` 或 `Check\n` 后，主程序等待 `UART3_GetRxFlag()`，取得 `UART3_GetRxData()`。返回数据按以下方式处理：

| 接收结果 | 主程序执行 |
| --- | --- |
| `'6'` | 返回循环，不执行分类动作 |
| `'1'`～`'4'` | 打开挡板，调用对应类别的托盘倾倒 |
| 完整抓取帧，最后一个字符为 `\n` | 读取 `RxInfo`，调用 `Catch(info.x, info.y, 85, info.type)` |
| `'9'` | 执行平均距离检测，清除 `check_flag`，复位托盘与挡板 |

对于倾倒指令，程序实际通过 `react_data & 0x0F` 将 ASCII 数字的低四位转成类别编号。对于抓取帧，接收函数完成整帧后，最后的 `RxData` 是换行，因此主程序以 `react_data == '\n'` 判断进入抓取分支。

当前实现没有先对所有字符做完整的合法性验证。例如收到其他字符时，也可能落入按低四位取值的分支。因此串口调试要使用协议规定的字符，不随意发送带回车换行的杂项文本。

### 6. 单个目标和同类目标：托盘倾倒

单个目标、或同一张图中所有目标属于同一大类时，上位机只发送类别字符，不发送坐标。STM32 把挡板设为 80°后，调用 `Low_Servo_React()`。

| 类别指令 | 垃圾类别 | 水平舵机 PA0 | 俯仰舵机 PA1 |
| --- | --- | --- | --- |
| `'1'` | 有害垃圾 | 45° | 140° |
| `'2'` | 厨余垃圾 | 135° | 140° |
| `'3'` | 可回收物 | 45° | 48° |
| `'4'` | 其他垃圾 | 135° | 48° |
| 复位 | 接料位置 | 90° | 94° |

水平转动使用每次变化 1°、等待 20 ms 的方式靠近目标；俯仰调用直接写目标角度。主程序执行倾倒后等待 1 秒，再设置 `break_flag=0`、`check_flag=1`。

随后调用 `Low_Servo_Reset()`，先让水平与俯仰回到 90°、94°，等待 200 ms，再将挡板设为 52°。下一轮不等待新的红外触发，而是向树莓派发 `Check\n`，检查有没有残留垃圾。

`Low_Servo_RotateHorizontal()` 的循环起点按 90°附近编写，依赖调用前机构已复位，并不是从任意实际角度平滑转到目标的通用函数。调试时如果跳过复位直接调用，运动行为可能与预期不同。

### 7. 混合目标：机械爪抓取

`Catch()` 接收四个参数：图像 X、图像 Y、夹爪旋转目标和垃圾类别。主程序固定把旋转目标传为 85°。

抓取过程按源码顺序如下：

| 步骤 | 函数或动作 | 参数/等待 | 目的 |
| --- | --- | --- | --- |
| 1 | `Core_XY(point_x, point_y, 1000, 1)` | 图像坐标模式 | 移到目标上方 |
| 2 | `Low_Servo_SetGuard(80)` | 挡板打开 | 为后续转移让位 |
| 3 | `Arm_Servo_SetCompareRevolve(angle)` | 主程序传 85° | 调整夹爪朝向 |
| 4 | `Arm_Servo_SetCompareDown(20)` | 等待 500 ms | 两个伸缩舵机共同下降 |
| 5 | `Arm_Servo_SetCompareGrab(105)` | 等待 1000 ms | 夹取物体 |
| 6 | `Arm_Servo_SetCompareDown(70)` | 无单独等待语句 | 抬起物体，随后还会进行托盘转动 |
| 7 | `Low_Servo_RotateHorizontal(45)` | 逐步转动 | 调整下部通道 |
| 8 | 按类别执行机械坐标移动 | 见下表 | 将物体运到对应桶上方 |
| 9 | 等待后开爪 | 先等 100 ms，开至 40°，再等 500 ms | 释放物体 |
| 10 | `Low_Servo_RotateReset()` | 按 46°到 90°写角度 | 恢复托盘水平旋转参考 |
| 11 | 经过中间点，旋转设回 85° | 按类别选择路径 | 返回并避让 |
| 12 | 挡板 52°，`Core_XY(0,0,1000,0)` | 机械坐标模式 | 回初始位置 |

类别投放路径不是根据摄像头即时计算，而是保存在代码中的固定坐标：

| 类别 | 去程 | 投放时旋转舵机角度 | 返回中间点 |
| --- | --- | --- | --- |
| 1 有害 | 到 `(210,10)` | 170° | `(100,100)` |
| 2 厨余 | 经 `(160,190)` 到 `(210,240)` | 85° | `(100,100)` |
| 3 可回收 | 到 `(0,240)` | 85° | `(50,190)` |
| 4 其他 | 经 `(50,50)` 到 `(0,0)` | 85° | 无额外中间点 |

这些坐标属于本机机械坐标体系，实际单位与脉冲换算需要按机构标定。换桶位、改变框架或改变夹爪尺寸后，应重新验证路线，不能直接让机构高速跑到这些坐标。

若抓取发生在 `check_flag=0` 阶段，主程序把 `break_flag` 设为 1，使下一轮再发送 `Start`。这样混合目标抓走一个后，会重新判断剩下的垃圾是否已经全部同类；如果已经同类，就可以整体倾倒。

若已经进入 `Check` 阶段，上位机对剩余目标继续发送抓取帧，直到无目标时返回 `'9'`。因此 `Start` 和 `Check` 的策略不同，不只是函数名字不同。

### 8. CoreXY 坐标换算与步进脉冲

#### 8.1 两种坐标输入

`Core_XY(input_X, input_Y, speed, type)` 的 `type=0` 表示直接输入机械坐标，`type=1` 表示先把图像坐标转换为机械坐标。

省赛代码中的仿射系数为：

```text
x = -0.442060 × u - 0.001511 × v + 204.414347
y = -0.002453 × u + 0.447338 × v + 18.974381
```

接着在 `Core_XY()` 中又加了安装偏移：

```text
X_target = point.x + 44
Y_target = point.y - 22
```

这里 `point.x`、`point.y` 的类型是 `uint16_t`，所以程序先把仿射结果转成整数，再加偏移。标定时既要核对仿射系数，也要核对这两个偏移；上位机不能先转一次，再把结果按图像模式送进来。

还要在转换后检查范围。负数结果、`point.y < 22` 或超出机械行程的坐标，不应直接进入无符号坐标变量后驱动电机。

#### 8.2 从平面位移到电机脉冲

程序保存当前位置 `X_current`、`Y_current`，计算与目标的差值：

```text
dx = X_target − X_current
dy = Y_target − Y_current

stp_1 = (dx − dy) × 160
stp_2 = (dx + dy) × 160
```

脉冲正负用于决定方向，脉冲数量用于决定移动距离。两台电机共同形成 XY 位移，因此交换电机、改变皮带绕向或反转电机方向后，都需要重新核对这套符号关系。

系数 160 是当前程序的标定常数。注释记录为 32 细分、每圈 6400 脉冲，但最终是否对应每毫米 160 脉冲，还要同时确认轮的齿数、齿距和驱动器设置。先用小范围移动测量实际位移，再确定换算关系。

`X_current`、`Y_current` 上电初始化为 0，完成发脉冲后直接更新为目标值；STM32 没有读取实际位置确认。因此即使驱动器没有报警，外力滑动、皮带打滑或错误回零都会让软件坐标与实际位置不一致。

#### 8.3 `speed` 参数的含义

代码通过 `(SystemCoreClock / 1000000) * (1000 / speed) - 1` 设置 TIM4 分频，再使用 `period=49`。这里有整数除法，`speed` 并不与实际速度连续线性对应，也不是 mm/s。

不能传入 0，否则发生除零；也不要超出代码预期范围。单电机、72 MHz 时钟且 `speed=1000` 时，定时器更新间隔按配置约为 50 μs，但实际脉冲还受软件轮询影响。

双电机函数中的两个分支读取并清除同一个更新标志，不能把它当作严格同步的硬件双轴插补。高速运行前应先低速观察轨迹，再用示波器或逻辑分析仪验证脉冲。

`Core_XY()` 中还需要检查一个方向分支：当 `stp_1<0` 且 `stp_2==0` 时，代码将左脉冲取正，却令 `dir_1=1`，与其他左负向分支使用的 `dir_1=0` 不一致。复刻时应先修正并验证这个方向分支，再测试相关对角线运动。目标与当前位置完全相同时，也应直接返回，避免将未赋值的方向变量传入底层函数。

### 9. 满载检测不是简单地读四个数

#### 9.1 单路测距

`MeasureDistance()` 对指定 Trig 输出 10 μs 高电平，再等待 Echo 变高，用 TIM6 记录高电平宽度，最后按以下公式计算厘米值：

```text
distance_cm = echo_time_us × 0.0343 / 2
```

四路顺序测量，每路之后延时 100 ms，以减少前一次发射对后续测量的影响。代码中的 `timeout=50000` 是循环次数递减，不是准确的 50000 μs 超时计时。

#### 9.2 转动托盘进行多位置测量

`HC_SR04_Get_Average_Distances()` 先将水平、俯仰复位，等待 500 ms，然后依次在水平 70°、90°、110°附近采集四路测距结果，最后将水平设回 90°。

注意实际语句顺序是写入一个新角度后立即开始测距，500 ms 延时位于这一组测量之后。这意味着不能声称每次测量前都已经等待舵机稳定。复刻时应检查实际运动时间，必要时把稳定等待明确放在写入角度之后、开始测量之前。

#### 9.3 平均方式、阈值与状态编号

| 传感器 | 使用的采样姿态 | 满载阈值 | 满载消息 | 未满消息 |
| --- | --- | --- | --- | --- |
| 1 | 70°、90°、110°三次平均 | 小于 16 cm | `Four\n` | `Fempty\n` |
| 2 | 70°、90°、110°三次平均 | 小于 16 cm | `Two\n` | `Tempty\n` |
| 3 | 70°、90°、110°三次平均 | 小于 16 cm | `Three\n` | `Rempty\n` |
| 4 | 70°、90°两次平均 | 小于 13.8 cm | `One\n` | `Oempty\n` |

第四路虽然也采集第三次数据，但平均公式只使用前两次。以上明确写出当前行为，不能把它笼统理解为“四路各取三次平均”。

消息编号与传感器编号不是 1 对 1 顺排，安装完成后要依次把物体放到每个探头下方，观察 OLED 和 Qt 界面变化，再确定桶位标签。不要仅根据 `One` 这个名称把探头接成第一路。

超时返回 `-1`，当前平均函数没有剔除该值，可能把无效测量当成很近的物体而误报满载。应先区分有效距离和错误状态，再计算平均值；不能为了消除误报只把满载阈值改小。

### 10. 串口协议和接收状态机

#### 10.1 报文内容

| 方向 | 数据 | 含义 |
| --- | --- | --- |
| STM32 → 树莓派 | `Start\n` | 新一轮或混合抓取后的再次识别 |
| STM32 → 树莓派 | `Check\n` | 倾倒后的残留复检 |
| STM32 → 树莓派 | `One/Two/Three/Four` 加换行 | 对应状态满载 |
| STM32 → 树莓派 | `Oempty/Tempty/Rempty/Fempty` 加换行 | 对应状态未满 |
| 树莓派 → STM32 | `'1'`、`'2'`、`'3'`、`'4'` | 四类垃圾的整体倾倒 |
| 树莓派 → STM32 | `'5' + XXX + YYY + C + '\n'` | 按图像坐标抓取 |
| 树莓派 → STM32 | `'6'` | 解锁接收流程 |
| 树莓派 → STM32 | `'7'` | 压缩操作 |
| 树莓派 → STM32 | `'8'` | 主动满载检测 |
| 树莓派 → STM32 | `'9'` | `Check` 没有检测到目标 |

单字符命令按 ASCII 发送，不附加换行；坐标帧最后必须有一个换行。实际抓取帧共 **9 字节**：1 字节 `'5'`、3 字节 X、3 字节 Y、1 字节类别、1 字节换行。

例如 X=123、Y=85、类别=3：

```python
packet = b"51230853\n"
# 拆分：b"5" + b"123" + b"085" + b"3" + b"\n"
```

Python 使用 `:03d` 格式化坐标，它只保证至少三位，超过 999 不会自动截断。发送前应校验坐标和类别，接收端也应拒绝非数字、越界坐标和错误长度。

#### 10.2 状态机怎样读取抓取帧

| 状态 | 等待或执行内容 | 下一状态 |
| --- | --- | --- |
| 0 | 等 `'6'`，收到后置接收标志 | 1 |
| 1 | 等普通指令；收到 `'5'` 进入坐标接收 | 2 |
| 2 | 收满 7 个有效载荷字符，存入缓冲区 | 3 |
| 3 | 等待 `\n`，完整帧置接收标志、清计数 | 1 |

`UART3_GetRxInfo()` 从前三位取 X、中间三位取 Y、最后一位取类别。转换方式是数字字符低四位乘百位、十位和个位，没有额外检查字符确实是 `'0'` 到 `'9'`。

状态 3 收到错误结束符时没有完整的超时恢复逻辑，丢字节或发送格式不符会导致后续接收错位。独立测试时，先重启控制板，再发送 `'6'`，再用已知报文检查解析结果，之后才接入运动流程。

#### 10.3 中断里执行长动作的问题

接收到 `'7'` 时，中断直接调用 `Condense()`，其中包含两段 10 秒等待；接收到 `'8'` 时，中断直接执行挡板操作、测距和复位。这样的长动作会占用串口中断，并影响同级中断和后续消息处理。

改进时应让接收中断只保存命令和置位标志，把压缩或满载检测放到主循环中执行。本文说明当前控制逻辑和复刻注意点，不把它当作已经具备完整异常恢复能力的通用控制框架。

## 树莓派视觉、Qt 界面与模型训练

### 1. Python 工程结构及启动入口

使用 `software/raspberry-pi/main.py`。本目录由省赛 Python 压缩包展开：

```text
software/raspberry-pi/
├── main.py                 # 应用入口、串口线程、识别和界面桥接
├── qml/
│   ├── main.qml            # 主窗口与页面加载器
│   ├── Mainpage.qml        # 首页，进入识别页时发送解锁指令
│   ├── Cvpage.qml          # 识别结果、计数、满载状态与操作按钮
│   ├── Checkpage.qml       # 另一个界面页面
│   ├── Videopage.qml       # 视频展示页
│   ├── UI_2.1/             # 界面图片资源
│   └── 1.mp4               # 展示视频
├── yolo/
│   ├── best.pt             # 部署权重
│   └── pics/               # 带检测框的结果图片
└── Makefile
```

不要把 `qml/` 里的另一个 `main.py` 当作默认启动入口。根目录应用依赖 `yolo/best.pt`、`qml/main.qml` 等相对路径，启动时的工作目录必须正确。

依赖包括 `ultralytics`、OpenCV、pyserial 和 PySide6。操作系统、Python 和库版本需要在实际树莓派环境中验证后锁定；不能只依据源文件 imports 保证任意最新版本都可以直接运行。

### 2. 程序启动后做了什么

主入口依次建立 `QGuiApplication`、`QQmlApplicationEngine` 和 `VideoFrameProvider`，将图像提供器注册为 `videoFrameProvider`。

`TestSystem` 对象初始化时：

1. 通过 `YOLO("yolo/best.pt")` 加载模型。
2. 以 115200 打开 `/dev/ttyAMA0`。
3. 初始化识别次数、显示序号和四个满载状态变量。
4. 启动运行 `serial_receive()` 的 QThread。

随后把 `TestSystem` 以 `videoCapture` 名称暴露给 QML，加载 `qml/main.qml` 并进入 Qt 事件循环。

所以模型文件错误、串口不存在或没有权限，都可能使程序在显示正常界面前就失败。排查时应分别验证这三件事，不要先怀疑摄像头或 STM32。

### 3. `serial_receive()`：树莓派等待谁来触发

树莓派不是一直对摄像头每一帧做分类，而是等待 STM32 发来的消息：

- 收到 `Start`：打开编号 0 的摄像头，读取一帧，调用 `test_send()`，再释放摄像头。
- 收到 `Check`：同样拍摄一帧，调用 `check()`，再释放摄像头。
- 收到满载/未满消息：修改 `one`、`two`、`three`、`four`，向 QML 发 `is_full` 信号。

串口读取使用 `readline().decode('utf-8').strip()`，因此 STM32 发来的文本应以换行结束。当前接收端没有完善的读取超时和异常恢复；遇到缺失换行或设备断开时，需要检查实际阻塞和错误行为。

摄像头每次重新打开后只取一帧。如果发现亮度不稳定或首次画面发暗，应检查曝光稳定时间，再决定是否预热后取帧；这属于需要验证的改进，并非当前代码已经做了多帧筛选。

### 4. `test_send()`：第一轮识别如何决定倒还是抓

调用 `self.model.predict(frame, conf=0.7, verbose=False)` 后，程序绘制检测框，将结果保存到 `yolo/pics/test_序号.jpg`，同时更新界面图像。

对每个检测框，程序读取模型类别名，再通过 `trash_dict()` 映射为四类垃圾：

| 四类垃圾 | 模型类别名 |
| --- | --- |
| `harmful` 有害 | `battery`、`drug` |
| `kitchen` 厨余 | `potato`、`carrot`、`daikon` |
| `recycle` 可回收 | `plastic`、`metal`、`cup` |
| `others` 其他 | `brick`、`cobblestone`、`porcelain` |

随后按检测结果决定：

| 结果 | 发送行为 |
| --- | --- |
| 只有一个目标 | 发对应类别字符，整体倾倒 |
| 多个目标，但映射后都是同一大类 | 发一个类别字符，整体倾倒 |
| 多个目标，包含不同大类 | 选择一个目标，发坐标抓取帧 |

同类判断比较的是四大类。例如两个不同的模型名称只要都映射为 `recycle`，就可以走同类倾倒。

抓取目标的选择不是距离最短或置信度最高：`test_send()` 把有害垃圾放到列表尾部，其他类别插到列表头部，再取第一个。所以其效果是在这个列表策略下优先取非有害目标，而不是经过抓取难度计算的最佳目标。

坐标来自 `box.xywh` 的前两项，即检测框中心 X、Y。程序没有用分割掩码或夹爪接触点估计，也没有对相邻物体进行抓取空间检查。两个物体靠近时被同时抓起，正与这一策略的局限相关。

**首次识别没有检测框时，当前函数会随机取一个模型类别，显示并发送倾倒指令。** 这不是识别成功。正式复刻建议改成有限次数重拍和未识别提示，不把这个分支计入准确率或正确分类数量。

### 5. `check()`：倾倒后怎样清理残留

`check()` 使用相同的模型阈值及图像保存流程，但决策不同：有目标就选一个并发送坐标抓取帧；没有目标就发 `'9'`。它不会因为剩余目标全部同类而再次发送整体倾倒指令，也没有首次识别函数中的随机分类分支。

`check()` 选择目标时使用列表插入顺序，不保留 `test_send()` 中有害类别后置的规则。不能把两个函数理解为完全相同的检测函数。

主程序收到 `'9'` 后进行满载检测、托盘复位并回到等待投料。这个闭环是“拍照—执行—重新拍照”，但没有夹爪上的抓取成功传感器；识别到的目标是否真正落入正确桶，需要通过整机测试确认。

### 6. Qt 图像、数量和按钮如何连接

图像显示流程为：OpenCV 结果图 → BGR 转 RGB → `QImage` → `VideoFrameProvider.update_image()` → `frame_ready` 信号 → QML 刷新 `image://videoFrameProvider/frame`。

数量显示使用 `find_trash` 信号。单目标或同类批量时，程序在发出动作指令之前就发出计数信号，并不是收到机械动作完成确认后计数。`check()` 中也没有相同的逐个计数逻辑。因此界面统计反映的是当前代码中的识别/指令记录，不能直接作为成功入桶数量。

主要按钮与命令的关系如下：

| 界面操作 | Python 方法 | 串口内容 |
| --- | --- | --- |
| 首页进入识别页面 | `unlock()` | `'6'` |
| 压缩按钮 | `condense()` | `'7'` |
| 满载检测按钮 | `checkFull()` | `'8'` |
| 首页退出按钮 | QML `Qt.quit()` | 不发送串口命令 |

退出按钮当前退出 Qt 应用，不等于关闭树莓派操作系统。基础版本未连接压缩机构时，不使用压缩按钮。

`main.qml` 的自动切换计时器 `interval` 为 50000，即约 50 秒。显示页面与图像资源仍需保持目录关系，屏幕分辨率变化时应同时调整布局。

满载状态的显示顺序需要与传感器表一起校准。不要把界面第一行、协议 `One`、传感器 1 和类别编号 1 当成天然一致的四个概念。

### 7. 数据准备与模型训练

#### 7.1 在最终装置上采集

先固定镜头、托盘高度、黑色覆盖件和补光，再采集图像。数据需要包含：单个垃圾不同朝向、托盘中心和四角、多个同类目标、混合目标、相邻和遮挡场景，以及空托盘。

先做一批小样本训练与部署，检查识别类别、坐标和实际抓取是否一致，再扩大数据量。否则可能花很多时间标注了与最终摄像头和照明条件不一致的数据。

#### 7.2 标签与类别保持配套

`tools/dataset/legacy/tool_1.py` 按 80%/20% 随机划分训练和验证图片，并复制同名标签。使用前需修改路径、检查标签是否齐全，并记录划分方式。连续拍摄的近似画面宜按批次分组，避免验证集与训练集过于相似。

`tool_2.py` 会直接改写标签编号，将若干细分类合并成四类。它不能不加检查地用于省赛权重：省赛 Python 按具体物体名称查 `trash_dict()`，如果模型已经变成只有四个大类名称，需同步修改应用映射。

运行任何标签重写脚本前，先保留未修改数据。训练数据配置中的 `names`、标签编号、部署权重的 `model.names` 与 Python 映射应作为一套版本保存。

#### 7.3 训练和推理脚本

训练入口位于 `tools/vision/train.py`，从仓库根目录显式指定初始权重与数据配置：

```sh
python3 tools/vision/train.py --weights models/local/initial.pt --data datasets/local/data.yaml --epochs 500
```

命令中的文件需要先准备好。程序先检查路径，再加载权重并训练，输出默认放入 `outputs/training/`。500 是请求训练的轮数，不是已经完成训练的证据，也不是自动续训配置。

图像测试入口为 `tools/vision/test.py`：

```sh
python3 tools/vision/test.py --source datasets/local/test_images
```

默认加载本地 `software/raspberry-pi/yolo/best.pt`，结果按 `result_0.jpg` 等保存到 `outputs/test_result/`。可以通过 `--weights` 和 `--output` 指定其他位置。图像测试不连接摄像头或 STM32。

历史脚本和训练资料仍保存在本地 `.local-archive/original/代码/树莓派/`，标签处理脚本在 `tools/dataset/legacy/`。验证通过后，再将确定的权重放入应用的 `yolo/best.pt`，记录模型来源、类别定义和验证结果。

没有完成实测前，不填写推测的准确率、FPS 或分拣成功率。

### 8. 重新标定图像坐标

`tools/calibration/main.py` 使用 19 组点，通过最小二乘拟合二维仿射关系。实际矩阵构造使用 `dst` 作为输入、`src` 作为输出，变量名称不应替代对真实数据含义的确认。

标定步骤：

1. 完成机械回零，确认机械坐标原点和正方向。
2. 在托盘上选择覆盖整个区域的标记点，记录其图像中心坐标。
3. 小范围移动夹爪，记录夹爪实际对准每个标记时的机械坐标。
4. 整理成一一对应的数据，明确输入是像素、输出是机械坐标。
5. 拟合转换系数，并检查固件中额外 `+44/-22` 偏移是否仍需要。
6. 使用没有参与拟合的点测试误差，记录四角、边缘和中心的偏差。
7. 将确认后的系数写入 `transform_coordinates()`，加入可达范围检查。

只在拟合用的 19 个点上打印误差，不能代表新位置也准确。摄像头调整后必须重做标定，机械回零重复性不好时也不应先靠改系数掩盖误差。

### 9. 手动部署、运行与自启动

树莓派使用 Ubuntu 24.04.1 LTS 桌面版的配置过程，以及 SSH、Python 3.10.16、PyTorch 和 YOLOv8 安装命令，见 [树莓派 YOLOv8 环境配置](raspberry-pi-yolov8-setup.md)。[完整 TXT 命令记录](搭建yolov8环境.txt) 同时保留，配置仍需在目标设备上重新验证。

先在树莓派上建立实际可用的环境，再记录系统版本、Python 版本及各依赖版本。确认以下项目后，从仓库根目录执行 `sh software/raspberry-pi/run.sh`，启动器会进入应用目录并运行 `main.py`：

1. 权重可加载，类别名称与映射匹配。
2. 摄像头编号正确，能稳定读取图像。
3. 串口实际存在、已启用、权限正确，TX/RX 接线已验证。
4. `qml/` 图片和视频资源完整，屏幕触控可用。
5. `yolo/pics/` 存在并有写入权限。
6. STM32 已完成单模块调试，运动区域没有障碍。

进入识别页面后，应用发送 `'6'`。等约 15 秒回零等待条件满足，确认设备进入待机，再放入第一个测试物体。

手动启动稳定后再配置开机自启动。启动配置必须指定实际 Python 解释器、工作目录、图形会话和日志位置。自启动还应能处理串口或摄像头暂未就绪的情况。当前资料没有核实可直接沿用的最终自启动文件，需在实际系统上配置并通过冷启动测试。

应用会不断保存结果图片。`Makefile` 中的 `clean` 会删除 `yolo/pics/` 下的 JPG，清理前先保留需要分析的测试图片。

## 分阶段调试与整机制作验收

### 1. 先制作一个不会自动运行全套动作的调试版本

正式主程序会在初始化时设置多个舵机位置，并启动回零等待计时。装配过程中应使用单模块调试入口，逐个验证外设，再恢复完整 `main.c`。保存调试版本和正式版本，避免临时改动后忘记恢复。

先不装机械负载，验证各路 PWM 与标记对应；再安装舵盘、连杆和托盘。运动测试从小角度、小位移开始，不直接执行完整抓取函数。

### 2. 舵机逐路标定

| 次序 | 操作 | 观察结果 |
| --- | --- | --- |
| 1 | PA6 旋转舵机设到装配参考位 | 只有旋转舵机动作 |
| 2 | PA7 从张开参考向夹紧方向小幅变化 | 夹爪开合方向正确，无连杆卡死 |
| 3 | PB0、PB1 分别检查，再共同输出 | 两侧伸缩方向配合，机构不扭曲 |
| 4 | PA0、PA1 分别验证水平和俯仰 | 托盘不会与桶、框架或线束碰撞 |
| 5 | PA2 先接一面挡板，再接四面 | 四面开合方向一致，关闭时不会互相顶住 |

标定表应记录实际采用的初始角、工作角、可用范围和舵盘安装方向。修改舵盘位置后，应重新检查相关全部动作，而不是只测试复位一次。

### 3. 回零和机械坐标验证

先验证继电器上电时序，再验证两个限位开关在预期位置动作。回零完成后，在空载情况下做短距离正 X、负 X、正 Y、负 Y 移动，观察方向和位移。

然后测试只需一台电机运动的两条对角线，以及连续多次往返。确认没有卡滞和丢失位置后，才验证 `(210,240)` 等投放位置。不能在坐标原点尚未确认时直接运行抓取程序。

断电重新启动，多次记录滑台实际回零位置。如果偏差已经大于夹爪可接受的范围，应先调整回零机构和限位，之后再做视觉标定。

### 4. 串口独立测试

先让 STM32 只记录收到的类别和坐标，不带动机构。核对 115200、8N1，发送 `'6'` 解锁，再验证单字符命令和抓取帧。

测试抓取帧时分别使用 X/Y 的一位、两位和三位数值，确认 Python 补零与 STM32 解析一致。再模拟错误字符、缺少换行和超范围坐标，检查程序会不会停在错误状态；补全恢复处理后再进入整机联动。

串口监视工具不能与主应用同时占用同一个设备。完成监视测试后关闭工具，再启动应用。

### 5. 超声波和桶位检查

先按说明修正 PB15 初始化，单独连接一路测试距离，再加入其余三路。将平整物体放在探头前不同距离，确认读数变化合理，并观察没有回波时返回的错误值。

四路都正常后，再执行托盘 70°、90°、110°多姿态测量。记录桶为空、接近满和已满时的读数，按实际探头位置重新确认阈值。

逐桶模拟满载并观察界面，检查四件事是否一致：探头编号、物理桶位置、发送消息和界面显示位置。若出现“遮住一个桶，另一个桶显示满”，优先排查映射，不立即调阈值。

### 6. 单目标和同类多目标

先从每类一个目标开始，分别验证四个倾倒方向。物体放在托盘中心、边缘和四角时都要测试，观察是否卡在覆盖件接缝、挡板或桶沿。

再放入多个同类目标，检查一次倾倒后是否有残留，`Check` 是否能发现并继续抓取。界面上的识别数量与实际入桶数量分别记录，不混为一个指标。

### 7. 混合垃圾和连续运行

依次测试两类混合、三类混合、相邻摆放和局部遮挡。每次保存检测图和实际结果，区分以下失败类型：

- 类别识别错了。
- 类别正确，但检测框中心不适合抓取。
- 定位偏移，夹爪没有对准。
- 抓取成功，但移动途中掉落。
- 相邻物体被连带抓起。
- 放入了错误桶位。
- 托盘有残留，但复检没有检测到。

连续测试时同时记录每轮耗时、是否重新回零、是否有控制板重启以及电池状态。优先解决可重复出现的问题，再调整速度。

### 8. 完成外壳后复测

安装遮光外壳后重新进行图像测试和四个方向的运动测试。检查外壳是否压线、是否改变照明、是否影响触控和取桶。最后进行多次冷启动，验证应用启动、串口解锁、15 秒等待和第一轮投料流程。

| 软件/模型版本 | 测试场景 | 次数 | 正确入桶次数 | 平均耗时 | 主要失败原因 |

## 常见问题与待完善项

| 现象 | 优先检查 |
| --- | --- |
| 上电后不进入工作 | 是否在界面进入识别页面并发送 `'6'`，`Start_Flag` 是否约 15 秒后置位 |
| 第二台步进电机提前通电或始终没电 | PB6 高低电平、继电器触发极性、常开/常闭触点 |
| 机构到不了预期位置 | 回零、方向分支、脉冲系数、皮带张力及坐标转换偏移 |
| 第四路超声波异常 | PB15 是否按 GPIOB 初始化、模块地和 Echo 接线 |
| 空桶显示满载 | 是否把 `-1` 测量失败值参与了平均；探头是否照到框架 |
| 报文到达但没有动作 | 是否先发 `'6'`、是否混入额外回车、坐标帧长度是否正确 |
| 一次误报后还继续错误分类 | 首次识别无目标时的随机分支是否仍启用 |
| 舵机上电就撞机构 | 舵盘参考位、程序初始角和实际机械装配是否对应 |
| 两个伸缩舵机互相顶住 | 相同角度下两侧连杆安装方向是否正确 |
| 开了界面但不能识别 | 摄像头编号、串口路径、权重路径和工作目录 |
| 改分辨率后抓取位置偏移 | 是否重新标定，像素坐标是否超过三位协议范围 |
| 界面数量与实际垃圾数量不同 | 计数在动作前更新，复检路径没有相同计数逻辑 |
| 切到其他界面或重进页面后显示异常 | QML 页面状态、图像提供器连接及局部计数是否重新初始化 |

在进一步完善源码时，优先处理以下项目：

1. 修正超声波 PB15 初始化，剔除无效测距并增加真实超时。
2. 取消首次识别失败后的随机分类，增加重拍及未识别状态。
3. 增加坐标范围检查，修正 CoreXY 特定负方向分支并验证脉冲同步。
4. 将串口中断中的长动作移到主循环，补全报文错误恢复。
5. 明确回零完成反馈，完善上电后实际位置与软件原点一致性检查。
6. 将机械执行成功与界面统计分开，增加动作完成状态。
7. 评估主循环与中断共享标志的访问方式，包括 `Start_Flag`、`UART3_RxFlag` 等变量的 `volatile` 和同步处理。

这份教程依据省赛源码解释现有实现，修正片段和改进项需要应用到实际工程后重新编译、烧录及验证。未列出实测结果的部分，不视为已完成硬件验收。
